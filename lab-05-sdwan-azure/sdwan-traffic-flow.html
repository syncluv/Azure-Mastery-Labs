Where the movement stops

Limitation 1 · pfSense
Rules never reach the running filter
Every rule on the unassigned WireGuard tab looked right in the GUI. pfctl -sr | grep -i wg1 showed zero compiled rules. Assigning the tunnel as a real interface fixed compilation, but each rule still emerged with a TCP-only flags S/SA clause baked in.
Limitation 2 · WireGuard
AllowedIPs is a source filter, not just a route
A correct route is not enough: a peer silently drops packets whose source it does not explicitly recognize. Widening AllowedIPs at every hop of the A→Hub→B failover path, verified by show configuration, still did not pass traffic.
